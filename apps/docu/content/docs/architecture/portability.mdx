The **shipped** path is [Vercel](/docs/deployment/vercel) + Supabase — a Vercel-optimized default, not a lock-in. GCP and AWS are not first-class deploy targets (product non-goal). The runtime is still ordinary Node, Fastify HTTP, Next.js, and PostgreSQL, so a later move is a host change, not a rewrite.

Do not read this page as “configure GCP or AWS from this repo.” Those remain unresolved.

## What is portable

- **Runtime (Node.js 24.x, LTS Krypton)**: Runs on Vercel, a VPS, or a container with no platform-specific application code.
- **API (Fastify)**: Standard HTTP. Serverless function, container, or VM. Exit is Fastify `listen`.
- **Agents (eve)**: Hello app in `apps/agents`. Default deploy is a sibling Vercel project (not required for this workspace). Exit is `eve build` → Nitro and `eve start`. [Eve](/docs/architecture/eve).
- **Web (Next.js)**: Vercel or self-hosted Node. Avoid vendor-only features if you expect to leave Vercel.
- **Database (PostgreSQL + Drizzle)**: Switch `POSTGRES_URL`. Local Product Ready uses Supabase CLI Postgres. Preview migrations require `RUN_PG_MIGRATE=true` and an isolated `POSTGRES_URL`; they cannot target a shared database.
- **Edge**: CDN, WAF, redirects, auth precheck, geo, cache. Not the core API, not eve, not Drizzle.

## Deployment options

Preview migrate requires `RUN_PG_MIGRATE=true` and an isolated `POSTGRES_URL`. Configure environment variables and deploy via the documented Vercel and Supabase flows.
