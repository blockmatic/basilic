Four planes:

- **Control** — Fastify product HTTP. `POST /ai/generate` stays. `POST /ai/chat` is demo chrome scheduled to retire once eve command and chat agents land.
- **Interaction and execution** — eve on a separate host. Hello lives in `apps/agents` — [Eve](/docs/architecture/eve). Not a Fastify proxy. No coordinator agent.
- **Domain** — `@repo/db` named functions and `@repo/markets` vendor HTTP. Next keeps `@repo/core`.
- **Presentation** — json-render on Next. `composeSurface` in `apps/web/lib/genui` builds Specs. Board chrome lives on [Frontend](/docs/architecture/frontend).

Models are implementation details; agents are product capabilities (`command`, `chat`). Fastify `getProvider()` resolves language models for `/ai/generate` and demo `/ai/chat`. Eve hosts Jev: `getEvaluationModel()` plus `evaluateBoardTurn` in `apps/agents/lib/evaluate` call `experimental_evaluate` on Vercel AI Gateway (`typesafe-ai/jev`). Unset `AI_GATEWAY_API_KEY` (and no `VERCEL_OIDC_TOKEN`) returns a null model and skips the hop. Jev judges refuse / canned / surface; it does not author json-render trees. The command agent wires that hop on `step.started`. Chat still lands later. Do not treat Commands as a Fastify `ToolLoopAgent`. Runtime decision: [ADR 014](/docs/adrs/014-fastify-eve-vercel-runtime).

Fastify `/ai/*` is **control-plane API chrome**, not the Product Ready bar and not the durable agent runtime. Agent **skills** (`AGENTS.md`, Basilic `/w-*`) live in [AI Workflow](/docs/development/ai-workflow) — not this page.

The Fastify API exposes two AI endpoints under `/ai/*`. Implementation lives in `apps/api/src/lib/ai/`; route files in `apps/api/src/routes/ai/` are thin handlers (schema + auth + delegation). The browser talks to Fastify directly (Bearer). There is no Next.js AI BFF.

There is no first-class OpenAI SDK, no RAG or embeddings, no chat message store, no `ToolLoopAgent`, and no mobile assistant. Chat is `streamText` / `generateText` with `stopWhen: isStepCount(AI_TOOL_MAX_STEPS)` and `maxOutputTokens` from `AI_MAX_OUTPUT_TOKENS` (default 4096). Client tool `output` / `errorText` on `dynamic-tool` and `tool-invocation` parts is stripped before `convertToModelMessages`. `body.model` is an allowlist scoped to the resolved provider (`default`, `haiku`/`sonnet` where that provider maps them, that provider's runtime default, plus `AI_DEFAULT_MODEL` on every provider). Unknown ids including `opus` are 400 even when no provider is configured. Cross-provider ids (for example `anthropic/claude-haiku-4.5` on Anthropic) are 400 before `getProvider`. `POST /ai/chat` and `POST /ai/generate` use a tighter route rate limit (`AI_RATE_LIMIT_MAX`, default 20) than global `RATE_LIMIT_MAX`. `GET /coins` is tighter still (`COINS_RATE_LIMIT_MAX`, default 10).

## Routes

| Route | Use case | Response |
|-------|----------|----------|
| `POST /ai/chat` | Demo chrome: multi-turn messages, tools. Retire after eve command+chat | JSON `{ text }` or UI-message SSE |
| `POST /ai/generate` | CLI, scripts, single prompt. **Stays** | JSON `{ text }` or UI-message SSE |

Both require Bearer auth (session JWT or API key). Set `Accept: text/event-stream` or `stream: true` for SSE. Generate is prompt-only (no tools).

## Provider chain

When `AI_PROVIDER` is unset, resolution order is **Anthropic → Open Router → Ollama if `OLLAMA_BASE_URL` is set** (`getResolvedProvider()` in `lib/ai/provider.ts`). Missing keys and no Ollama URL yields `null` (500 `SERVER_ERROR`). Request alias `sonnet` maps to Claude Sonnet 4.6; default model is Haiku 4.5.

For Ollama installation and ops, see [Self-Hosted LLM](/docs/deployment/self-hosted-llm). The example pull model there is `qwen2.5:3b`; the runtime default when using Ollama is `qwen3:8b`.

## `lib/ai` layout

```
apps/api/src/lib/ai/
  index.ts           named re-exports
  provider.ts        getResolvedProvider, getProvider, model allowlist
  messages.ts        UIMessage / CoreMessage → ModelMessage; strip tool output
  route-rate-limit.ts /ai/* Fastify rateLimit config
  download.ts        denyRemoteChatFileDownload (blocks non-data: fetches)
  runtime.ts         abort, SSE piping, upstream error mapping
  upstream-error.ts  isInsufficientCreditsError
    tools/
    index.ts              re-exports getMergedTools
    account-info.ts       getMergedTools + getAccountInfo
    market-snapshot.ts    getMarketSnapshot
    brave-search.ts       braveSearch (when BRAVE_SEARCH_API_KEY set)
```

Shared runtime handles client abort + `AI_UPSTREAM_TIMEOUT_MS`, v7 UI streams (`toUIMessageStream` + `createUIMessageStreamResponse`), and catalog errors via `captureError` then `sendCatalogError`.

Client `{ role: 'system' }` messages are rejected with 400. There is **no** server `instructions` / system prompt — the model sees `user` and `assistant` messages plus tool descriptions. Client roles are limited to `user` and `assistant`; `tool` and other roles return 400.

File parts in UIMessage payloads must use `data:` URLs only (`maxLength` 2048). Remote URLs (`http:`, `https:`, `file:`, etc.) are rejected at validation with 400 before the handler runs. Defense in depth: TypeBox `^data:` pattern → `resolveMessages` / `isAllowedChatFileUrl` → `experimental_download` (`denyRemoteChatFileDownload`) so the AI SDK never fetches remote file URLs.

## Environment variables

| Variable | Required | Default | Description |
|----------|----------|---------|-------------|
| `ANTHROPIC_API_KEY` | Conditional (preferred) | — | Anthropic direct API |
| `OPEN_ROUTER_API_KEY` | Conditional (fallback) | — | Open Router when Anthropic unavailable |
| `OLLAMA_BASE_URL` | Conditional | — | Self-hosted Ollama (not inferred from localhost) |
| `AI_PROVIDER` | No | Inferred | `anthropic`, `openrouter`, or `ollama` |
| `AI_DEFAULT_MODEL` | No | Provider-specific | Haiku / `anthropic/claude-haiku-4.5` / `qwen3:8b` |
| `AI_TOOL_MAX_STEPS` | No | `5` | Max tool-loop steps for chat |
| `AI_MAX_OUTPUT_TOKENS` | No | `4096` | Completion cap (`maxOutputTokens`) |
| `AI_RATE_LIMIT_MAX` | No | `20` | Per-route `/ai/*` max in the rate-limit window |
| `AI_UPSTREAM_TIMEOUT_MS` | No | `120000` | Upstream abort timeout (ms) |
| `BRAVE_SEARCH_API_KEY` | No | — | Enables optional `braveSearch` tool |

Templates: `apps/api/.env.defaults.example`, `apps/api/.env.test.example`. Jev Gateway credentials live on the eve host (`apps/agents/.env.defaults.example`): optional `AI_GATEWAY_API_KEY`, `JEV_MODEL` (default `typesafe-ai/jev`), `AI_EVALUATE_TIMEOUT_MS`. Do not put `AI_PROVIDER=jev` on Fastify.

## Fastify chat tools (demo chrome)

The dashboard does not mount this assistant. Presentation (board Spec, `composeSurface`) is [Frontend](/docs/architecture/frontend). Do not wire `useChatFromConfig` from the dashboard.

**Demo jobs (API tools, not dashboard UI):** `getAccountInfo` (`__render: 'user-info'`) and `getMarketSnapshot` (`__render: 'market-card'`). `braveSearch` is optional and not a demo completion job. Matching catalogs live under `apps/web/components/assistant`. There is no GenUI CTA (`actions: {}`).

`getAccountInfo` output:

```json
{ "__render": "user-info", "spec": { "root": "...", "elements": { ... } }, "summary": "..." }
```

`getMarketSnapshot` output:

```json
{ "__render": "market-card", "spec": { "root": "...", "elements": { ... } }, "summary": "..." }
```

`getMarketSnapshot` calls `getMarkets` (the same in-process cache as JWT `GET /coins`). On 429 or network failure it returns checked-in fixture rows so fork-and-run does not need a CoinGecko key. Card `source` is `live` or `fixture` (never `mock`).

Multi-turn history for `POST /ai/chat` is the request `messages` array only — nothing is persisted.

## Errors

Pre-stream failures map to catalog codes: 401, 400, 402 (`INSUFFICIENT_CREDITS`), 429 (`RATE_LIMIT_EXCEEDED`), 502 (`UPSTREAM_SERVICE_ERROR`), 504 (`UPSTREAM_TIMEOUT`). Response bodies use catalog messages only — never raw upstream `err.message`.

## Testing

- **API Vitest** (`ai.spec.ts`, `lib/ai/provider.spec.ts`): `test/utils/ai-remote.ts` skips **402** only when the response is `INSUFFICIENT_CREDITS` (quota is infra). Skips 502/504/connection only when `ANTHROPIC_API_KEY` is missing or placeholder `sk-ant-xxx`. A real key → 502 fails the suite.
- Board chrome and `composeSurface` tests: [Frontend](/docs/architecture/frontend) and [E2E Testing](/docs/testing/e2e-testing). There is no chat Playwright project.
