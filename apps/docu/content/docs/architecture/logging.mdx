---
title: "Logging"
description: "Server: Pino via @repo/utils/logger/server. Client: console wrapper via /logger/client. Never console.* in app code."
---

```ts
import { logger } from '@repo/utils/logger/server'  // Fastify, Next server, scripts
import { logger } from '@repo/utils/logger/client'  // 'use client'

logger.info({ userId: '123' }, 'User logged in')
```

Fastify routes should use `request.log` so request context is attached. Child loggers: `logger.child({ requestId })`. Server logs redact secrets. Client logs are off in production unless you raise the level.

In CI, `NODE_ENV=test`, or when `VITEST` is set, the default level is `silent`. Override with `LOG_LEVEL`. Config lives next to env validation in each app — not a global constants file.

Product analytics (PostHog) is not logging: [Analytics](/docs/architecture/analytics). Failures go to [Error Handling](/docs/architecture/error-handling).
