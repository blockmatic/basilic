`apps/web` consumes `@repo/core` and `@repo/ui`. `apps/mobile` is a UI scaffold: it may share **tokens** later, not components or generated API types today. `apps/docu` uses `@repo/ui` only — it does not depend on `@repo/core` or `@repo/react`. It loads the same Inter, Poppins, and Geist Mono CSS variables as `apps/web`. Web → Core; Error → Web.

## Routing

- [`proxy.ts`](/docs/architecture/authentication) is the UI auth gate (shared `JWT_SECRET`). Fastify remains session issuer and revocation. Web auth/session/cookie: Next client → Next route → SDK → Fastify. Domain data: browser SDK → Fastify Bearer.
- Unauthenticated requests never reach the App Router 404: `apps/web/proxy.ts` redirects them to `/auth/login`. After auth, unmatched paths render `apps/web/app/not-found.tsx` with HTTP 404.
- When dynamic resource routes exist, call `notFound()` for missing resources — not inline “not found” JSX with a 200 status.
- No parallel (`@slot`) or intercepting routes until the product needs a multi-pane or modal-detail UI.
- Crawl (`apps/web` only): `app/robots.ts` allows `/privacy`, `/terms`, `/auth/login`, and `/sitemap.xml`, disallows `/`, and advertises the sitemap at `NEXT_PUBLIC_APP_URL`. `app/sitemap.ts` emits absolute `loc` URLs from that origin. Docs-host crawl policy: [Vercel Deployment — Docs host crawl](/docs/deployment/vercel#docs-host-crawl).

## Errors

`app/error.tsx` and the shared `ErrorBoundary` report via `captureError` from `@repo/error/nextjs`, same as `global-error.tsx`. See [Error Handling](/docs/architecture/error-handling).

## Rendering (RSC-first)

Default to Server Components. Use `'use client'` only for interactivity, browser APIs, or client-only libraries.

Stream with `loading.tsx` and Suspense. Mark search/filter updates as transitions when they would block the UI.

### Caching

`apps/web` uses the **legacy** Next 16 cache model: `cacheComponents` is off, so `'use cache'` is unused. Do not enable Cache Components without a migration.

- Do not export `dynamic = 'force-dynamic'` from the root layout. That sets `fetchCache: 'force-no-store'` for the route and voids fetch-level `next.revalidate`.
- [`proxy.ts`](/docs/architecture/authentication) gates requests. Cookie reads there do **not** make RSC segments dynamic. A page becomes dynamic when a Server Component calls `cookies()` (for example `getUserInfo` → `getServerAuthToken`).
- Coin board: RSC `createLoader` reads the URL `SearchQuery` plus ViewConfig fields (`surface`, `period`, `columns`, `elements`) and chrome (`q`, `sidebar`, `rail`) via `loadBoardView` + `loadChrome` (`clearOnDefault`). First HTML matches `?sidebar=close` / `?rail=chat` as well as the composed spec. `surface=account` overlays `universe=watchlist` for that fetch and paints catalog `UserInfo` from `$state.account` (`getUserInfo`) plus the favorites table. `surface=chart` paints Line/Area/Bar recipes bound to `$state.series` from JWT `GET /coins/:assetId/candles` (default asset `bitcoin`, `period` default `7d`). When `elements` is set, `specFromSelection` rebuilds the Spec from allowlisted candidate ids and does not call Jev. The client island hydrates the same parsers with shallow `history: 'push'` for board keys and `history: 'replace'` for chrome keys. Share copies `location.href`. Chip writes set SearchQuery and clear `q` and `elements`. Do not set `shallow: false`. Do not put `version` or a JSON ViewConfig blob on the query string. Unmapped Binance pairs stay honest in the chart island; they do not embed OHLC in the Spec.
- Semi-static RSC data still using `fetch` with `next: { revalidate: N }`: unused headlines helper (`NEWSAPI_KEY`).
- Auth / Fastify: `cache: 'no-store'`. Identical GET `fetch` calls are request-memoized; do not wrap them in `React.cache()`.
- No `revalidateTag` until something is tagged. Mutations stay on Fastify, not Server Actions.

## Mutations

Forms and hooks call the shared API client (`@repo/core`, `@repo/react`) which hits Fastify directly. Next.js routes exist only for SSR and cookie integration — auth callbacks, logout, `POST /api/auth/refresh` (browser 401 hop; never Fastify refresh from the browser), and `POST /api/auth/update-tokens` (same-origin, Fastify-validated before `Set-Cookie`). Do not migrate login or settings mutations to `'use server'`.

Pending and optimistic UI for mutations stays on TanStack mutation flags (`isPending`, `isError`); do not rewrite forms to `useFormStatus` or `useOptimistic`.

### Server vs client fetch

- **RSC:** home coin board (`createLoader` + `listCoins` + `specFromSelection` or `composeSurface` + `getUserInfo` into `$state.account`) and profile (`getUserInfo` in the page, `initialData` on `useUser`).
- **Client TanStack:** coin-board island hydrates a json-render `Renderer` with `StateProvider` `{ coins, sync, account }`, then refetches and watch stars; settings/security (API keys, passkeys, TOTP). Security surfaces are mutation-first and need WebAuthn or OTP browser APIs. Do not duplicate their GETs in Server Components; an empty first paint until hydration is accepted. Commands canned **Who am I?** writes `surface=account` and `q`, and appends `{ command, viewConfig }` to `sessionStorage`; history rows restore nuqs with `history: 'push'` and keep `q`. Spoken-query chips write SearchQuery and **clear `q` and `elements`**. Share copies the current href (clipboard + toast). Typed Commands Send uses `GET /agents` then eve `command` (`set_view` → nuqs), then Next `composeBoardSpec` to persist `elements`. The shared composer can dictate via Web Speech (`SpeechRecognition` / `webkitSpeechRecognition`) into the same input; pause does not send. HTTPS or localhost. Missing ctor hides the mic. Chat Send uses eve `chat` with `boardQuery` / `viewConfig` / `elements` as canvas context and does not compose. Fastify has no `/ai/chat`. ComposeSpec is a `'use server'` module in `lib/genui`; it is not re-exported from the client barrel and is not a Fastify domain BFF.

```tsx
import { parseAsInteger, parseAsString, useQueryStates } from "nuqs"

const [filters, setFilters] = useQueryStates({
  search: parseAsString.withDefault(""),
  page: parseAsInteger.withDefault(1),
})
```

## UI

`@repo/ui` owns shadcn-style components on Base UI primitives, and Tailwind 4. Import `@repo/ui/components/*`. Primitive composition: `@repo/ui/base` (never `@base-ui/react` or `@radix-ui/*` from apps). Prototype in v0 if useful, then install into `@repo/ui` (`components.json` style `base-vega`) and consume from apps.

Compose with Base UI `render` (and `nativeButton={false}` when the node is not a button), not Radix `asChild`. Style parts with `data-slot` and open/checked with `data-open` / `data-checked` (Tailwind `data-open:*`, not `data-[state=open]:`). Full attribute list: [ADR 013](/docs/adrs/013-shadcn-base-ui).

The dashboard composer lives on the coin board (`Commands` | `Chat` chrome inside the same client island as the table). Dictation is Web Speech into that box (review, then Send). The board catalog is `apps/web/lib/genui` plus `apps/web/components/genui` (names map to `@repo/ui`). Catalogs in `apps/web/components/assistant` stay as chat fallbacks. Fastify has no `POST /ai/chat`; Chat Send uses eve. Agent UI work: `/ui` for surfaces. Reuse `@repo/ui` before new primitives (`/shadcn`). Compound APIs: `composition-patterns`. Visual direction stays `frontend-design`; existing tokens win. Brand and palette rules: root `DESIGN.md`. UI code checklist: `web-design-guidelines`. Do not add a second design skill or generate `DESIGN.md` from `tokens.css`.

## Web3 (apps/web)

The Fastify API supports Web3 auth and account linking (EIP-155 / Solana). `apps/web` ships a custom searchable wallet modal (`lib/wallet` registry + `@/components/wallet`) using wagmi EIP-6963, optional WalletConnect (`NEXT_PUBLIC_WALLETCONNECT_PROJECT_ID`), and Wallet Standard for Solana. Import connectors from `wagmi/connectors/injected` and `wagmi/connectors/walletConnect` (not the `wagmi/connectors` barrel — webpack would pull Coinbase/`@x402`). Login is linked-wallets only; Settings links/unlinks. `@repo/react` keeps verify helpers (`useVerifyWeb3Auth`, `useVerifyLinkWallet`, `useUnlinkWallet`). See [Authentication](/docs/architecture/authentication) and [Account linking](/docs/architecture/account-linking).

## Testing

Frontend apps use Playwright E2E. Board compose (`composeSurface`, `specFromSelection`, mock composeSpec evaluator) is Vitest in `apps/web/lib/genui` (not a React Testing Library suite). Speech merge/ctor helpers are Vitest in `apps/web/lib/speech`. See [E2E Testing](/docs/testing/e2e-testing). Playwright specs are not a substitute for the `/ui` rendered pass (desktop and mobile screenshots plus keyboard). Visual-regression CI is not shipped.
