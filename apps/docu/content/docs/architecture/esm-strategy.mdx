Packages are `"type": "module"`. Workspace apps import TypeScript source; `prepack` switches exports to `dist/` for npm. Details of the publish switch: [Publishing](/docs/deployment/publishing).

## Dual-mode exports

**Pattern A** (`@repo/core`, `@repo/react`): `import` points at `src/` in the workspace.

**Pattern B** (`@repo/utils`, `@repo/error`, `@repo/email`, `@repo/notif`): `source` for bundlers, `node` / `import` / `default` for compiled `dist/` so serverless resolvers do not hit `ERR_MODULE_NOT_FOUND`.

Prefer subpath imports (`@repo/utils/async`). Do not deep-import `src/`.

## TypeScript 7 and 6

TypeScript 7 is the native Go `tsc` (`"@typescript/native": "npm:typescript@^7.0.2"`). Use it for `build` and `checktypes`. It does not yet ship a programmatic API, so ESLint and Next.js keep TypeScript 6 via `"typescript": "npm:@typescript/typescript6@^6.0.2"`. Next.js 16.3 would call `typescript/bin/tsc`; set `experimental.useTypeScriptCli: false` so it uses the TS 6 API instead.

Shared configs live in `tools/typescript` (`base.json`, `nextjs.json`, `react-library.json`). `ts-reset` is on. `types: ["*"]` restores automatic `@types/*` (TS 7 defaults `types` to `[]`).

## Resolution

| Runtime | `moduleResolution` | Relative imports |
| --- | --- | --- |
| Next.js 16, React libraries | `bundler` | extensionless OK |
| Fastify / Node | `NodeNext` | use `.js` in the import path (emit), never `.ts` |

Node dev: `tsx`. Next: `transpilePackages` plus webpack `conditionNames: ['source', …]` and `.js` → `.ts` `extensionAlias` (required in Next 16.3.3 — Turbopack lacks `resolveExtensionAlias`). Scripts pass `--webpack` until Turbopack supports workspace `.js` imports. Import `@repo/*`, not relative paths into `packages/`.

Generated OpenAPI client (`packages/core/src/gen/`) and skill templates are excluded from hand-maintained TS rules. Conventions: `.cursor/rules/base/typescript.mdc`.
