GitHub Actions workflows automate quality checks on pull requests (opened and updated).

## Workflows

Path filters are used only for test workflows (app E2E and package unit tests) so they run when relevant code changes. Lint and `security.yml` run on every PR. DeepSec runs on same-repo PRs only. Path patterns are defined in each workflow file.

### Web (`web-e2e.yml`)

Build → Unit → E2E. Triggers on pull request when `apps/web/**`, shared packages, or openapi change. Single job: build (with localhost API URL), unit tests, E2E via `test:e2e:local` (spawns Fastify + Next locally).

### API (`api-e2e.yml`)

Build → Unit → E2E. Triggers on pull request when `apps/api/**` or shared packages change. Single job: build, unit tests, E2E via `test:e2e:local` (spawns API locally, runs Scalar login E2E).

### Packages (`packages-test.yml`)

Unit tests for shared packages (core, react, sentry, etc.). Triggers on pull request when `packages/**` or `tools/**` change. Excludes app tests (handled by api-e2e, web-e2e).

### Docu (Vercel)

No dedicated CI workflow. Docu deploys via Vercel from Git with `turbo-ignore`; builds run only when `apps/docu/**` or shared packages change.

See [E2E Testing](/docs/testing/e2e-testing) for details.

### Lint (`lint.yml`)

Linting and type checking on every PR. Supports `workflow_dispatch` for manual runs.

### Mobile (`mobile-build.yml`, `mobile-preview.yml`, `mobile-pr-preview.yml`)

EAS builds and PR OTA previews for the Expo app. Requires `EXPO_TOKEN` in GitHub Secrets. v1: Android-only, no store submission.

- **mobile-build**: Manual trigger. Builds Android preview or development profile.
- **mobile-preview**: Push to `main` (paths: `apps/mobile/**`, `packages/ui/**`). Builds Android preview; refreshes baseline for OTA.
- **mobile-pr-preview**: Pull request (paths: `apps/mobile/**`, `packages/ui/**`). Publishes EAS Update, comments QR code. Reviewers must install baseline preview APK first; then scan QR to load PR update.

See [Mobile CI/CD](/docs/deployment/mobile-cicd) for setup, reviewer bootstrap, and JS-only OTA limits.

### Security (`security.yml`)

Security scans (gitleaks, TruffleHog, OSV Scanner, pnpm audit) on every PR and push to main. DeepSec is not in this workflow; see DeepSec (`deepsec.yml`).

### DeepSec (`deepsec.yml`)

Source-code review of the PR diff on same-repo pull requests. Fork PRs skip (no secrets). Two jobs:

1. **analyze** — `contents: read` only. Installs `.deepsec`, writes credentials to `.deepsec/.env.local`, runs GPT-5.6 Sol (`codex`, thinking `medium`) `process --diff` against the PR base. Fails on net-new findings. Requires `AI_GATEWAY_API_KEY` (recommended) or `OPENAI_API_KEY` in repository secrets. Local alternate: Cursor Grok 4.6 via `pnpm security:deepsec:process:diff:grok`.
2. **comment** — `pull-requests: write`. Posts the findings comment. Never checks out or executes PR code.

Full-repo DeepSec review stays local. See [Security](/docs/architecture/security).

## CodeRabbit Integration

CodeRabbit automatically reviews pull requests using AI. Configuration is in `.coderabbit.yaml`:

```yaml
# .coderabbit.yaml (simplified)
language: en-US
reviews:
  auto_review: true
  high_level_summary: true
```

See the complete `.coderabbit.yaml` in the repository root for full configuration.

## Pre-commit Hooks

Local quality checks run before each commit:

```json
// package.json (simplified)
{
  "simple-git-hooks": {
    "pre-commit": "pnpm run hooks:pre-commit"
  }
}
```

Pre-commit hooks check:
1. **File blocking** - Prevents committing sensitive files (`.env`, `*.pem`, etc.)
2. **Secret scanning** - Scans staged files with gitleaks
3. **Formatting** - Runs Biome formatter on staged files

## Best Practices

1. **Run checks locally** - Fix issues before pushing
   ```bash
   pnpm lint
   pnpm checktypes
   pnpm test
   ```

2. **Review CodeRabbit suggestions** - Learn from AI feedback and iterate

3. **Keep workflows fast** - Use caching and parallel jobs

4. **Test before merge** - Ensure all checks pass before merging

5. **Monitor CI failures** - Fix broken workflows immediately

## Workflow Files

All workflows are in `.github/workflows/`:
- `web-e2e.yml` - Next: unit → E2E (local servers, path-filtered)
- `api-e2e.yml` - API: unit → E2E (local servers, path-filtered)
- `packages-test.yml` - Packages: unit tests (path-filtered)
- `mobile-build.yml` - Mobile: manual EAS build (Android)
- `mobile-preview.yml` - Mobile: EAS build on push to main (path-filtered)
- `mobile-pr-preview.yml` - Mobile: EAS Update, QR comment on PR (path-filtered)
- `lint.yml` - Linting checks (every PR)
- `security.yml` - Secret and dependency scans (every PR and push to main)
- `deepsec.yml` - Source-code review of the PR diff (same-repo PRs)
