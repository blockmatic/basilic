GitHub Actions workflows automate quality checks on every pull request and push to main.

## Workflows

CI uses [dorny/paths-filter](https://github.com/dorny/paths-filter) so tests run only when relevant code changes. Path filters are defined in `.github/paths-filter.yml`.

### Next Unit Test (`next-unit-test.yml`)

Build and unit tests for the Next.js app. Runs when `apps/next`, `scripts/`, or dependencies (core, react, ui, utils) change.

- Build (`turbo build --filter=@repo/next...`)
- Unit tests (`turbo test --filter=@repo/next`)

### Next E2E Test (`next-e2e-test.yml`)

E2E tests for the Next.js app. Runs after Vercel deployment via `repository_dispatch` (success/error/failed only). See [E2E Testing](/docs/testing/e2e-testing).

### API Unit Test (`api-unit-test.yml`)

Build and unit tests for the Fastify API. Runs when `apps/fastify` or its dependencies (email, sentry, utils) change.

- Build (`turbo build --filter=@repo/fastify...`)
- Unit tests (`turbo test --filter=@repo/fastify`)

### API E2E Test (`api-e2e-test.yml`)

E2E tests for the Fastify API. Runs after Vercel deployment via `repository_dispatch` (success/error/failed only). See [E2E Testing](/docs/testing/e2e-testing).

### Docu CI (`docu-ci.yml`)

Build validation for the docs site. Runs when `apps/docu` or `packages/ui` change. No unit or E2E tests.

### Lint (`lint.yml`)

Linting and type checking on every PR. Runs on all changes.

### Security (`security.yml`)

Security scans (gitleaks, TruffleHog, OSV Scanner, pnpm audit) on every PR and push to main.

## CodeRabbit Integration

CodeRabbit automatically reviews pull requests using AI. Configuration is in `.coderabbit.yaml`:

```yaml
# .coderabbit.yaml (simplified)
language: en-US
reviews:
  auto_review: true
  high_level_summary: true
```

See the complete `.coderabbit.yaml` in the repository root for full configuration.

## Pre-commit Hooks

Local quality checks run before each commit:

```json
// package.json (simplified)
{
  "simple-git-hooks": {
    "pre-commit": "pnpm run hooks:pre-commit"
  }
}
```

Pre-commit hooks check:
1. **File blocking** - Prevents committing sensitive files (`.env`, `*.pem`, etc.)
2. **Secret scanning** - Scans staged files with gitleaks
3. **Formatting** - Runs Biome formatter on staged files

## Best Practices

1. **Run checks locally** - Fix issues before pushing
   ```bash
   pnpm lint
   pnpm checktypes
   pnpm test
   ```

2. **Review CodeRabbit suggestions** - Learn from AI feedback and iterate

3. **Keep workflows fast** - Use caching and parallel jobs

4. **Test before merge** - Ensure all checks pass before merging

5. **Monitor CI failures** - Fix broken workflows immediately

## Workflow Files

All workflows are in `.github/workflows/`:
- `next-unit-test.yml` - Next.js build + unit (path-filtered)
- `next-e2e-test.yml` - Next.js E2E (repository_dispatch)
- `api-unit-test.yml` - Fastify API build + unit (path-filtered)
- `api-e2e-test.yml` - Fastify API E2E (repository_dispatch)
- `docu-ci.yml` - Docs build validation (path-filtered)
- `lint.yml` - Linting checks
- `security.yml` - Security scans
