GitHub Actions workflows automate quality checks on every pull request and push.

## Workflows

CI uses [dorny/paths-filter](https://github.com/dorny/paths-filter) so tests and deploys run only when relevant code changes. Path filters are defined in `.github/paths-filter.yml`.

### Deploy and E2E (`deploy-and-e2e.yml`)

Unified pipeline: **unit tests → deploy → E2E tests**. Triggers on `push` and `pull_request` for all branches.

- **Unit phase**: Build and test Next.js when `next` scope changes; build and test Fastify API when `api` scope changes. No unit tests for docu.
- **Deploy phase**: Deploys changed apps to Vercel (next, fastify, docu) after unit tests pass. Uses Vercel CLI with production env for main/develop, preview for other branches.
- **E2E phase**: Runs only on pull requests. API E2E when `api` changes; Next E2E when `next` changes. URLs come from deploy job outputs.

See [E2E Testing](/docs/testing/e2e-testing) for details.

### Lint (`lint.yml`)

Linting and type checking on every PR. Runs on all changes.

### Security (`security.yml`)

Security scans (gitleaks, TruffleHog, OSV Scanner, pnpm audit) on every PR and push to main.

## CodeRabbit Integration

CodeRabbit automatically reviews pull requests using AI. Configuration is in `.coderabbit.yaml`:

```yaml
# .coderabbit.yaml (simplified)
language: en-US
reviews:
  auto_review: true
  high_level_summary: true
```

See the complete `.coderabbit.yaml` in the repository root for full configuration.

## Pre-commit Hooks

Local quality checks run before each commit:

```json
// package.json (simplified)
{
  "simple-git-hooks": {
    "pre-commit": "pnpm run hooks:pre-commit"
  }
}
```

Pre-commit hooks check:
1. **File blocking** - Prevents committing sensitive files (`.env`, `*.pem`, etc.)
2. **Secret scanning** - Scans staged files with gitleaks
3. **Formatting** - Runs Biome formatter on staged files

## Best Practices

1. **Run checks locally** - Fix issues before pushing
   ```bash
   pnpm lint
   pnpm checktypes
   pnpm test
   ```

2. **Review CodeRabbit suggestions** - Learn from AI feedback and iterate

3. **Keep workflows fast** - Use caching and parallel jobs

4. **Test before merge** - Ensure all checks pass before merging

5. **Monitor CI failures** - Fix broken workflows immediately

## Workflow Files

All workflows are in `.github/workflows/`:
- `deploy-and-e2e.yml` - Unit tests, Vercel deploy, E2E (path-filtered; E2E on PR only)
- `lint.yml` - Linting checks
- `security.yml` - Security scans
