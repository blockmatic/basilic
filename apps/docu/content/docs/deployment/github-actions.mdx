GitHub Actions workflows automate quality checks on pull requests (opened and updated).

## Workflows

CI uses path filters in each workflow so tests and deploys run only when relevant code changes. Path patterns align with `.github/paths-filter.yml`.

### Next (`next-e2e.yml`)

Build → Unit → E2E. Triggers on pull request when `apps/next/**`, shared packages, or openapi change. Single job: build (with localhost API URL), unit tests, E2E via `test:e2e:local` (spawns Fastify + Next locally).

### API (`api-e2e.yml`)

Build → Unit → E2E. Triggers on pull request when `apps/fastify/**` or shared packages change. Single job: build, unit tests, E2E via `test:e2e:local` (spawns API locally, runs Scalar login E2E).

### Docu (Vercel)

No dedicated CI workflow. Docu deploys via Vercel from Git with `turbo-ignore`; builds run only when `apps/docu/**` or shared packages change.

See [E2E Testing](/docs/testing/e2e-testing) for details.

### Lint (`lint.yml`)

Linting and type checking. Triggers on pull request when `apps/**`, `packages/**`, `tools/**`, `scripts/**`, or config files change. Supports `workflow_dispatch` for manual full-repo checks.

### Security (`security.yml`)

Security scans (gitleaks, TruffleHog, OSV Scanner, pnpm audit). Triggers on pull request when source files, lockfile, `package.json`, or security config change; always runs on push to main.

## CodeRabbit Integration

CodeRabbit automatically reviews pull requests using AI. Configuration is in `.coderabbit.yaml`:

```yaml
# .coderabbit.yaml (simplified)
language: en-US
reviews:
  auto_review: true
  high_level_summary: true
```

See the complete `.coderabbit.yaml` in the repository root for full configuration.

## Pre-commit Hooks

Local quality checks run before each commit:

```json
// package.json (simplified)
{
  "simple-git-hooks": {
    "pre-commit": "pnpm run hooks:pre-commit"
  }
}
```

Pre-commit hooks check:
1. **File blocking** - Prevents committing sensitive files (`.env`, `*.pem`, etc.)
2. **Secret scanning** - Scans staged files with gitleaks
3. **Formatting** - Runs Biome formatter on staged files

## Best Practices

1. **Run checks locally** - Fix issues before pushing
   ```bash
   pnpm lint
   pnpm checktypes
   pnpm test
   ```

2. **Review CodeRabbit suggestions** - Learn from AI feedback and iterate

3. **Keep workflows fast** - Use caching and parallel jobs

4. **Test before merge** - Ensure all checks pass before merging

5. **Monitor CI failures** - Fix broken workflows immediately

## Workflow Files

All workflows are in `.github/workflows/`:
- `next-e2e.yml` - Next: unit → E2E (local servers)
- `api-e2e.yml` - API: unit → E2E (local servers)
- `lint.yml` - Linting checks (path-filtered)
- `security.yml` - Security scans (path-filtered on PRs)
