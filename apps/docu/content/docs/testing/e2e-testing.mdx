---
title: "E2E Testing"
description: "Playwright E2E for Next.js and Fastify. Frontend apps have no separate unit suite."
---

Frontend apps have no separate unit suite. Two Playwright suites: **Web** (`apps/web`) for the product UI, **API** (`apps/api`) for Scalar login at `/reference`. Both use `test@test.ai` when `ALLOW_TEST=true`.

The Scalar page loads `@scalar/api-reference` from jsDelivr (pinned version in `reference/template.ts`). E2E depends on that CDN for the login button script.

Install Chromium with `pnpm setup:playwright` (or `pnpm setup`) if browsers are missing. Specs are not skipped.

Root `pnpm qa` ends with `pnpm test:e2e` (`scripts/run-e2e.mjs`). That script kills processes on ports 3000 and 3001 unless `SKIP_KILL_PORTS=1`.

## Commands

| Command | Description |
| --- | --- |
| `pnpm test:e2e` (root) | Fastify E2E, then Next E2E (spawns servers) |
| `pnpm --filter @repo/web test:e2e:local` | Build (unless `SKIP_BUILD=1`), spawn API + Next, run web E2E |
| `pnpm --filter @repo/api test:e2e:local` | Spawn API, run Scalar login E2E |
| `pnpm test:e2e:ui` / `test:e2e:debug` | Playwright UI or debug (in the app) |

Pass URLs with `--app` / `--api`, or `PLAYWRIGHT_APP_URL` / `PLAYWRIGHT_API_URL`. Defaults: `http://localhost:3000` and `http://localhost:3001`.

```bash
pnpm test:e2e --app=https://my-app.vercel.app --api=https://my-api.vercel.app
```

## Auth fixtures

Use **one worker** (PGlite cannot take concurrent writers). Auth project runs first (errors, login, logout). Authed tests import `authenticatedPage` from `e2e/fixtures` — one login per worker via `authenticatedStorageState` (`test-results/.auth/user.json`). Login/logout tests use a fresh `page` from `@playwright/test`.

```typescript
import { expect, test } from './fixtures'

test('should show dashboard when authenticated', async ({ authenticatedPage }) => {
  await authenticatedPage.goto('/')
  await expect(authenticatedPage.locator('text=Signed In')).toBeVisible()
})
```

Chat E2E needs `ANTHROPIC_API_KEY` (in-app Claude Sonnet 4). CI and `test:e2e:local` set `AI_PROVIDER=anthropic`.

## Magic link

`ALLOW_TEST=true` stores the token in `verification.token_plain` and exposes `/test/magic-link/last`. Local spawn scripts set it. For Vercel previews, set it on the Preview environment. The API process exits if `ALLOW_TEST` is true in production.

## CI and mobile

Path-filtered PR workflows: `api-e2e.yml`, `web-e2e.yml`, `packages-test.yml`. See [GitHub Actions](/docs/deployment/github-actions).

Expo uses Maestro (`apps/mobile/.maestro/flows/home.yml`). CI Maestro is deferred; see [Mobile CI/CD](/docs/deployment/mobile-cicd).

## Web specs

| Spec | Coverage |
| --- | --- |
| `magic-link-auth.spec.ts` | Login, token errors, protected route, JWT session |
| `chat-assistant.spec.ts` | Chat UI with `authenticatedPage` |
| `security/api-keys.spec.ts` | API keys CRUD |
| `security/authenticator.spec.ts` | TOTP setup/unlink |
| `security/passkeys.spec.ts` | Passkeys with CDP virtual authenticator |

Order: Auth project → Chromium → Security.

## Vercel protection (manual)

For protected previews: enable Protection Bypass for Automation on both projects with the same secret, set `VERCEL_AUTOMATION_BYPASS_SECRET`, and allowlist OPTIONS `/` or `/auth` on the API project.

## Troubleshooting

Ports in use: `bash scripts/kill-test-servers.sh`. Token extraction fails: confirm `ALLOW_TEST=true` and `test@test.ai`.
