## Context

The monorepo needs one lint and format toolchain that is fast enough for every save and for `pnpm qa`, covers TypeScript, React, Next.js, and Vitest, and can still encode package-boundary rules.

## Decision

Use **Ultracite** presets with **Oxlint + Oxfmt**. Config is generated from `ultracite init` at the repo root (`oxlint.config.ts`, `oxfmt.config.ts`). `pnpm lint` is `oxlint . && oxfmt --check .`. `pnpm lint:fix` and `pnpm format` run Oxlint fix then Oxfmt write. Pre-commit runs Oxfmt write after security hooks. CI (`lint.yml`) calls `pnpm lint`.

Package-boundary rules (no raw `process.env`, Next/eve/markets/onchain stay off `@repo/db` and `drizzle-orm`, `@repo/ui` / `@repo/utils` / Radix / Base UI subpath bans) live as overrides on the generated Oxlint config.

## Superseded: Hybrid Biome + ESLint

The previous split was Biome for format and style, ESLint (`@repo/eslint-config` in `tools/eslint`) for correctness and architecture. That shared config package and per-workspace `eslint.config.*` files are gone. Generated projects copy the root Oxlint and Oxfmt configs instead of `tools/eslint`.

A third linter (`react-doctor`) stays out: Ultracite's optional `js-plugins` preset is not enabled.
