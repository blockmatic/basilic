title: "ADR 014: Fastify, eve, and Vercel runtime"
description: "Keep Fastify as the product API. Adopt eve as the durable agent runtime on a separate host. Optimize for Vercel; keep a Node/container exit."
---

Status: **Accepted.** Companion to [ADR 002](/docs/adrs/002-backend-framework). E1 landed the hello workspace; E2 landed access-JWT, `@repo/markets`, and product ids `command`/`chat`. T4g landed Gateway Jev (`getEvaluationModel` / `evaluateBoardTurn`) on the eve host. G-cmd wired Commands to eve; G-chat wired the Chat tab to eve `chat`. R-ai retired Fastify `POST /ai/chat`.

## Context

Fastify is the scored product API: OpenAPI, auth, coins, and `POST /ai/generate`. Interactive Chat is the eve `chat` agent, not a Fastify route. Sessions, turns, Workflow, sandbox, and interactive streams do not belong on the Is Agentic Fastify host. The stack already sits on Vercel Functions, AI SDK, and Workflow. Edge Runtime is not the recommended host for the core API or for agents.

## Decision

Keep Fastify. Adopt eve. Optimize for Vercel. Preserve a Node/container exit. Use Edge selectively. Keep product logic independent of all of them.

- Fastify stays the product API. [ADR 002](/docs/adrs/002-backend-framework) holds.
- eve is the recommended **durable** agent runtime (Workflow-backed sessions) on a **separate** host. Do not mount `/eve/` on the scored Fastify URL.
- Default deploy is Vercel. Exit is ordinary Node / container: Fastify `listen`, `eve start`, and `eve build` → Nitro for the agent host.
- Core API = Node + Fluid Compute, not Edge Runtime wholesale. Edge is CDN, WAF, redirects, auth precheck, geo, and cache — not the API, not eve, not Drizzle.
- Domain functions live in `@repo/*`. `@repo/db` named fns and `@repo/markets` vendor HTTP are landed. Next keeps `@repo/core`. Fastify is not a database proxy for eve.
- Track A discovery (`llms.txt`, `/openapi.json`, RFC 9727 catalog) stays on Fastify. OpenAPI is the agent contract. There is **no product MCP**. If MCP is justified later, add a logically isolated capability surface inside Fastify — not a second application. Do not advertise MCP or `/eve/` from `llms.txt`.
- Fastify is the **control plane**, not a universal proxy. Interactive agent transport belongs to eve. No coordinator: two first-class agents (`command` and `chat`). `GET /agents` is discoverability (JWT), not the authorization boundary.

Four planes: Fastify control; eve interaction and execution; shared domain packages; GenUI presentation. Models are implementation details; agents are product capabilities. Jev on eve judges closed labels (refuse / canned / surface). On Commands Send, Next `experimental_composeSpec` lets Jev pick table/account candidates and writes the Spec; GET / chips restore from nuqs `elements` and do not re-run Jev. `composeSurface` remains the skip path. Do not treat Commands as a Fastify `ToolLoopAgent`.

## Consequences

- `apps/agents` is an eve workspace with JWT-gated `command` and `chat` agents. Commands and Chat UI talk to eve.
- `POST /ai/generate` stays. Fastify `POST /ai/chat` is gone; dashboard Chat uses eve.
- Two Vercel projects: Fastify Function + Fluid; eve on a sibling project (Workflow + Sandbox). Self-host proxies must keep `/eve/` and `/.well-known/workflow/` un-rewritten. The agents Vercel project is not required for this merge.
- Identity: Fastify mints JWT. Eve verifies **access** tokens. Nitro is eve’s server, not an identity provider. Channels are inbound ingress; connections are outbound.
