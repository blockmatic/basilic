Project skills live in `.cursor/skills/`. Cursor requires `name` in each `SKILL.md` to match the folder that contains it. That is why tech skills use a versioned dirname.

Rules override skills. Skills override the model. Indexed docs are advisory.

## Two kinds

**Tech** — `.cursor/skills/<topic>-v<major>/` (example: `fastify-v5`). Agent-invocable. Required sections: Scope, Assumptions, Principles, Constraints, Interactions. Force with `@.cursor/skills/<topic>-v<major>` or `/<topic>-v<major>`.

**Workflow** — `.cursor/skills/workflow/<name>/`. Slash-only. Set `disable-model-invocation: true`. One-line `description`. Not versioned. Type `/name` in Cursor. Claude Code has no `/` menu: read the `SKILL.md` file.

`name` is lowercase letters, digits, and hyphens, max 64 characters, equal to the folder name.

Skill descriptions are always in the agent’s discovery context. One folder per skill. Do not keep `foo/` next to `foo-v1/`. Prefer fewer, focused skills.

## Versioning

`<topic>-v<major>` is the **library or SDK major**, not a skill-file revision.

- Library major change → new folder (`next-v17`). Drop the old folder when the repo no longer uses that major.
- Upstream wording, references, or bugfixes → same folder; commit the file diff.
- Design skills with no npm package keep `-v1` until the skill format itself breaks (`frontend-design-v1`, `emilkowal-animations-v1`, `vercel-react-v1`). Library skills (including Motion) use the npm major (`motion-v13` for `motion` ^13).
- Workflows stay unversioned.

This repo’s Expo app is SDK 57; Expo skills are still `*-v55` because that is what upstream publishes. Do not invent empty `*-v57` folders. When Expo ships v57 skills, add those folders and drop v55.

## Vendor and overlay

Git is the source of truth. The team gets skills on clone. `npx skills` is a fetch tool only. Do not use `npx skills update` after rename: lock keys will not match upstream names.

Do not `git pull` inside a nested `.git` under `.cursor/skills/`. Do not store project skills only in `~/.cursor/skills/` (personal experiments only).

**Add or update a third-party skill**

1. Fetch into `/tmp`: `npx skills add owner/repo --skill <upstream-name> --agent cursor -p`, or a shallow clone.
2. Copy files into `.cursor/skills/<topic>-v<major>/`.
3. Overlay: set frontmatter `name:` to the folder name. Keep Basilic sections on tech skills we maintain. Restore repo notes (Playwright E2E stays in `apps/web/e2e` and `apps/api/test`).
4. Delete any unversioned sibling folder. Confirm with `ls .cursor/skills` before hunting leftovers.
5. Commit. Review the diff like any other vendored snippet.

When grepping skill names, match the folder or `name:` exactly (`motion-v1/`, `name: motion-v1`). Do not use a substring (`motion-v1` also hits `motion-v13`).

**Remove** — delete the folder, drop inventory rows, grep for `@.cursor/skills/…` links.

Root `skills-lock.json` tracks Expo CLI hashes only. It is optional and incomplete. Do not treat it as the full inventory.
