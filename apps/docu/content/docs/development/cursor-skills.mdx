Project skills live under `.agents/skills/`. The tree is **gitignored**; install with `pnpm setup:skills` from [`scripts/skills-lock-manifest.mjs`](https://github.com/blockmatic/basilic/blob/main/scripts/skills-lock-manifest.mjs). The CLI writes [`skills-lock.json`](https://github.com/blockmatic/basilic/blob/main/skills-lock.json) (hashes for CI). Use `--agent cursor` only so the canonical copy lands in `.agents/skills/` (not `.claude/` or `.cursor/skills/`). Do not use `skills experimental_install`.

Cursor requires `name` in each `SKILL.md` to match the folder (`nextjs`, not `next-v16`). Rules override skills. Skills override the model. Daily workflow: [AI Workflow](/docs/development/ai-workflow).

## Catalogs

**Basilic playbooks** — [blockmatic/basilic-skills](https://github.com/blockmatic/basilic-skills). Skill `workflow` installs nested `/w-*` under `.agents/skills/workflow/w-<name>/`. Slash names: `/w-plan`, `/w-grill`, `/w-wayfinder`, `/w-build`, `/w-review`, plus git close-out (`/w-commit` … `/w-ship`).

**Stack and craft** — upstream GitHub catalogs listed in `scripts/skills-lock-manifest.mjs` (Emil motion, Next.js, Expo EAS, Vercel agent-skills, json-render, eve, shadcn, and others). Do not restyle installed copies to match Biome; `biome.json` excludes `.agents/skills/**`. Repo-specific layout and style stay in `AGENTS.md` and `.cursor/rules/`.

## What’s in git

- `skills-lock.json` — pin record after install or catalog refresh
- `scripts/skills-lock-manifest.mjs` — which `--skill` names `setup:skills` installs per source
- `scripts/setup-skills.mjs` — runs the manifest, removes `.claude/` and `.cursor/skills/`

```bash
pnpm setup:skills
```

`pnpm setup` runs the same step.

## Three kinds

**Workflow** — Basilic playbooks at `.agents/skills/workflow/w-<name>/`. `disable-model-invocation: true` on playbooks. One-line `description`.

**Lock-installed skills** — upstream folder names (`nextjs`, `shadcn`, `vercel-composition-patterns`). Invoke with `@.agents/skills/<name>` or `/<name>` when the harness exposes slash skills.

**Rules** — always-on constraints (Fastify, wagmi, file layout, TypeScript). Stack topics with no published skill (Drizzle, TanStack Query, Fastify, Solana wallet flows) are covered here instead of forked `SKILL.md` trees.

`name` is lowercase letters, digits, and hyphens, max 64 characters, equal to the folder name. Basilic playbook names start with `w-`.

## Workflow install

**44** `/w-*` playbooks ship inside the `workflow` pack. `/w-plan` explores via `/w-council` first. Catalog validation: `node scripts/validate-catalog.mjs` in [blockmatic/basilic-skills](https://github.com/blockmatic/basilic-skills).

## Update procedure

1. Edit `scripts/skills-lock-manifest.mjs` (add/remove a source or `--skill` name).
2. Run `pnpm setup:skills`.
3. Commit `skills-lock.json` (and the manifest change).

Do not `git pull` inside nested `.git` under skills. Do not store project skills only in `~/.cursor/skills/`.

## Design

`DESIGN.md` and glob rules win over craft skills. UI work: `/w-ui`. New shadcn primitive: `/w-shadcn` (follow `@shadcn`). Component APIs: `@vercel-composition-patterns`. UI code audit: `@web-design-guidelines`. React/Next performance: `@vercel-react-best-practices`. Motion: `@animate` (web) or `@animate-expo` (native). Toasts: `@ask-sonner`. Do not run `@pick-ui-library` to replace shadcn in this repo.

This product uses Base UI (`base-vega`, `render`, `data-slot` / `data-open`). The official `shadcn` skill reads `components.json`.
