Project skills live under `.agents/skills/`. That path is the committed hub for Cursor, Codex, Antigravity, Gemini CLI, Copilot, and any agent that reads Agent Skills. The [skills CLI](https://github.com/vercel-labs/skills) interactive install lets you pick skills **and agents**. This repo’s lockfile refresh is `-a cursor --copy` into `.agents/skills/` (Codex shares that path). Claude Code’s default dir is `.claude/skills/`; do not `--copy` that tree into git. `CLAUDE.md` tells Claude to read `.agents/skills/` instead.

Cursor also reads `.cursor/skills/` if present; this repo does not commit that tree. Cursor requires `name` in each `SKILL.md` to match the folder (`fastify-v5`, not `fastify`).

Rules override skills. Skills override the model. Indexed docs are advisory. Daily playbooks: [AI Workflow](/docs/development/ai-workflow). Optional Cursor extras: [Agent setup](/docs/development/cursor-setup).

## Catalogs

**Tech and workflow** — [blockmatic/basilic-skills](https://github.com/blockmatic/basilic-skills) on [skills.sh](https://skills.sh/blockmatic/basilic-skills). Playbooks install as the parent `workflow` skill.

Install or refresh (interactive — pick skills and agents):

```bash
pnpm dlx skills@latest add blockmatic/basilic-skills
```

Non-interactive refresh used in this repo:

```bash
pnpm dlx skills@latest add blockmatic/basilic-skills --skill '*' -a cursor --copy -y
```

That writes tech skills under `.agents/skills/<name>/` and playbooks under `.agents/skills/workflow/<name>/`. Full installer options: catalog [README](https://github.com/blockmatic/basilic-skills#agents-and-paths). Examples: `-a claude-code`, `-a cursor -a claude-code`, `--agent '*'`. Optional maintainer-local Claude symlink (not committed): add `-a claude-code` **without** `--copy`.

Root `skills-lock.json` tracks catalog hashes. The `web-design-guidelines` entry also records the pinned `command.md` commit digest. Commit the lock with `.agents/skills/` after every refresh.

## Two kinds

**Tech** — `.agents/skills/<topic>-v<major>/` (example: `fastify-v5`). Agent-invocable. Required sections: Scope, Assumptions, Principles, Constraints, Interactions. Force with `@.agents/skills/<topic>-v<major>` or `/<topic>-v<major>`.

**Workflow** — install the parent `workflow` skill; nested children are not independent install targets. `.agents/skills/workflow/<name>/` (example: `workflow/plan`). Slash-only. Set `disable-model-invocation: true`. One-line `description`. Not versioned. Type `/plan` or `/build` in Cursor. If a harness has no matching menu, read the `SKILL.md` file directly.

`name` is lowercase letters, digits, and hyphens, max 64 characters, equal to the folder name.

Skill descriptions are always in the agent’s discovery context. One folder per skill. Do not keep `foo/` next to `foo-v1/`. Prefer fewer, focused skills.

## Workflow install

The published workflow package is `workflow`: `.agents/skills/workflow/SKILL.md` dispatches to 51 children, including `/plan`, `/build`, and `/use-frontend`. Shared authoring and completion references travel inside this tree.

This repository should have one workflow tree. Slash tags are `/workflow`, `/plan`, and `/build`. `/workflow plan` is a dispatcher shortcut to `/plan`. After a refresh, preserve local edits first, then run `pnpm dlx skills@latest remove --skill b -a cursor -y` if a leftover `b` tree appears. `.agents/skills/b/` must be absent afterward.

Packaging validation runs in the catalog with `pnpm validate`. It checks metadata, counts, grouping, and workflow reference targets. These checks do not prove that an agent follows the workflow or that a particular desktop menu has refreshed.

## Versioning

`<topic>-v<major>` is the **library or SDK major**, not a skill-file revision.

- Library major change → new folder (`next-v17`). Drop the old folder when the repo no longer uses that major.
- Upstream wording, references, or bugfixes → edit the catalog; re-run the skills CLI in this repo.
- Pattern, guideline, and craft skills stay unversioned (`frontend-design`, `emilkowal-animations`, `vercel-react`). Library skills (including Motion) use the npm major (`motion-v13` for `motion` ^13).
- Workflows stay unversioned.

This repo’s Expo app is SDK 57; Expo skills are still `*-v55` because that is what upstream publishes. Do not invent empty `*-v57` folders. When Expo ships v57 skills, add those folders in the catalog and drop v55.

## Update procedure

```bash
pnpm dlx skills@latest add blockmatic/basilic-skills --skill '*' -a cursor --copy -y
```

A named refresh is valid (`--skill next-v16`, `--skill workflow`). After a refresh, run `pnpm dlx skills@latest remove --skill b -a cursor -y` if `.agents/skills/b/` is present. That leftover path must be absent afterward.

Review the diff; commit `.agents/skills/` and `skills-lock.json`. Do not reformat skill copies to match this repo's Biome rules; `biome.json` excludes `.agents/skills/**`.

Do not `git pull` inside nested `.git` under skills. Do not store project skills only in `~/.cursor/skills/`.

Repo-specific overlays stay in `.cursor/rules/` (example: Playwright app E2E paths in `e2e-playwright.mdc`).

When grepping skill names, match the folder or `name:` exactly (`motion-v1/`, `name: motion-v1`). Do not use a substring (`motion-v1` also hits `motion-v13`).
