Project skills live under `.agents/skills/` after `pnpm setup` (or `pnpm setup:skills`). That path is gitignored. `skills-lock.json` must pin **only** `blockmatic/basilic-skills` (including vendored `react-email`). Setup runs one `skills add blockmatic/basilic-skills --skill '*'` (one Git clone), then writes the lock file back so hashes stay pinned. It fails on a second GitHub catalog or on `sourceType: local` unless `BASILIC_SKILLS_LOCAL=1` (then it adds `../basilic-skills`). Do not use `skills experimental_install`. To refresh hashes, run `skills add` yourself and commit the lock.

The [skills CLI](https://github.com/vercel-labs/skills) writes the tree for Cursor, Codex, Antigravity, Gemini CLI, Copilot, and any agent that reads Agent Skills. This repo’s install is `-a cursor --copy` into `.agents/skills/` (Codex shares that path). Claude Code’s default dir is `.claude/skills/`; do not `--copy` that tree into git. `CLAUDE.md` tells Claude to read `.agents/skills/` instead.

Cursor also reads `.cursor/skills/` if present; this repo does not commit that tree. Cursor requires `name` in each `SKILL.md` to match the folder (`fastify-v5`, not `fastify`).

Rules override skills. Skills override the model. Indexed docs are advisory. Daily playbooks: [AI Workflow](/docs/development/ai-workflow). Optional Cursor extras: [Agent setup](/docs/development/cursor-setup).

## Catalogs

**Tech, patterns, and workflow** — [blockmatic/basilic-skills](https://github.com/blockmatic/basilic-skills) on [skills.sh](https://skills.sh/blockmatic/basilic-skills). Playbooks install as the parent `workflow` skill. `react-email` is vendored in that catalog (upstream [resend/react-email](https://github.com/resend/react-email)).

Interactive pick (skills and agents):

```bash
pnpm dlx skills@latest add blockmatic/basilic-skills
```

Non-interactive install for this repo is `pnpm setup:skills` (Update procedure below). Full installer options: catalog [README](https://github.com/blockmatic/basilic-skills#agents-and-paths). Optional maintainer-local Claude symlink (not committed): add `-a claude-code` **without** `--copy`.

Root `skills-lock.json` tracks catalog hashes. The `web-design-guidelines` entry also records the pinned `command.md` commit digest. `pnpm setup:skills` restores that file after install. Commit the lock after an explicit catalog refresh. Do not commit `.agents/skills/`.

## Three kinds

**Tech** — `.agents/skills/<topic>-v<major>/` (example: `fastify-v5`). Agent-invocable. Required sections: Scope, Assumptions, Principles, Constraints, Interactions. Force with `@.agents/skills/<topic>-v<major>` or `/<topic>-v<major>`.

**Patterns** — unversioned craft and guidelines (example: `composition-patterns`, `frontend-design`, `vercel-react`). Agent-invocable. Same loading as tech skills.

**Workflow** — install the parent `workflow` skill; nested children are not independent install targets. Everyday leaves live at `.agents/skills/workflow/<name>/`; specialists may be `.agents/skills/workflow/<group>/<name>/` (example: `workflow/git/commit`). Slash is the leaf name. Set `disable-model-invocation: true`. One-line `description`. Not versioned. Type `/plan`, `/build`, or `/review` in Cursor. If a harness has no matching menu, read the `SKILL.md` file directly.

`name` is lowercase letters, digits, and hyphens, max 64 characters, equal to the folder name.

Skill descriptions are always in the agent’s discovery context. One folder per skill. Do not keep `foo/` next to `foo-v1/`. Prefer fewer, focused skills.

## Workflow install

The published package is `workflow`: `.agents/skills/workflow/SKILL.md` is the parent catalog for 45 children, including `/plan`, `/build`, `/review`, and `/ui`. Shared authoring, completion, and git-publish references travel inside this tree. The parent lists shortcuts and stops; it does not dispatch `/workflow plan`.

This repository should have one workflow tree. Invoke playbooks as `/<name>`. After a refresh, preserve local edits first, then run `pnpm dlx skills@latest remove --skill b -a cursor -y` if a leftover `b` tree appears. `.agents/skills/b/` must be absent afterward.

Packaging validation runs in the catalog with `pnpm validate`. It checks metadata, counts, grouping, and workflow reference targets. These checks do not prove that an agent follows a playbook or that a particular desktop menu has refreshed.

## Versioning

`<topic>-v<major>` is the **library or SDK major**, not a skill-file revision.

- Library major change → new folder (`next-v17`). Drop the old folder when the repo no longer uses that major.
- Upstream wording, references, or bugfixes → edit the catalog; re-run the skills CLI in this repo.
- Pattern, guideline, and craft skills stay unversioned (`frontend-design`, `emilkowal-animations`, `vercel-react`). Library skills (including Motion) use the npm major (`motion-v13` for `motion` ^13).
- Workflows stay unversioned.

This repo’s Expo app is SDK 57; Expo skills are still `*-v55` because that is what upstream publishes. Do not invent empty `*-v57` folders. When Expo ships v57 skills, add those folders in the catalog and drop v55.

## Update procedure

Install the tree without changing the lock:

```bash
pnpm setup:skills
```

Maintainer preview of a sibling catalog clone:

```bash
BASILIC_SKILLS_LOCAL=1 pnpm setup:skills
```

Refresh from GitHub (rewrites hashes in `skills-lock.json`; review and commit the lock):

```bash
pnpm dlx skills@latest add blockmatic/basilic-skills --skill '*' -a cursor --copy -y
```

A named refresh is valid (`--skill next-v16`, `--skill workflow`). After a refresh, run `pnpm dlx skills@latest remove --skill b -a cursor -y` if `.agents/skills/b/` is present. That leftover path must be absent afterward.

Review the lockfile diff; commit `skills-lock.json` only. Do not reformat skill copies to match this repo's Biome rules; `biome.json` excludes `.agents/skills/**`.

Do not `git pull` inside nested `.git` under skills. Do not store project skills only in `~/.cursor/skills/`.

Repo-specific overlays stay in `.cursor/rules/` (example: Playwright app E2E paths in `e2e-playwright.mdc`).

When grepping skill names, match the folder or `name:` exactly (`motion-v1/`, `name: motion-v1`). Do not use a substring (`motion-v1` also hits `motion-v13`).

## Design

UI craft also comes from [emilkowalski/skills](https://github.com/emilkowalski/skills): `/prototype`, `emil-design-eng`, animation vocabulary and review skills. Those folders sit next to tech and pattern skills, not under `workflow/`. Project tokens in `DESIGN.md` still win.

New or reshaped UI: `/ui`. Visual direction only: `@frontend-design` (tokens win when present). Component APIs: `@composition-patterns`. UI code audit: `@web-design-guidelines`. Quality a11y report: `/a11y`. Runtime bugs: `/debug-browser`. Explore variants: `/prototype`.
