Project skills live under `.agents/skills/`. **Tech and pattern** skills are committed in this repo (list in `scripts/owned-agent-skills.txt`). **Playbooks** and the [mattpocock/skills](https://github.com/mattpocock/skills) pack are installed by `pnpm setup:skills` and stay gitignored. `skills-lock.json` pins **exactly two** GitHub catalogs: `blockmatic/basilic-skills` (`w-*`) and `mattpocock/skills`. Setup restores the lock after install so hashes stay pinned. It fails on any other GitHub catalog or on `sourceType: local` unless `BASILIC_SKILLS_LOCAL=1` (then playbooks come from `../basilic-skills`). Do not use `skills experimental_install`. Do not also install Matt’s Claude Code plugin — that duplicates skills.sh copies.

The [skills CLI](https://github.com/vercel-labs/skills) writes the tree for any agent that reads Agent Skills. This repo’s install is `--all` into `.agents/skills/`. Claude Code’s default dir is `.claude/skills/`; do not commit that tree. `CLAUDE.md` tells Claude to read `.agents/skills/` instead.

Cursor also reads `.cursor/skills/` if present; this repo does not commit that tree. Cursor requires `name` in each `SKILL.md` to match the folder (`fastify-v5`, not `fastify`).

Rules override skills. Skills override the model. Indexed docs are advisory. Daily playbooks: [AI Workflow](/docs/development/ai-workflow). Optional Cursor extras: [Agent setup](/docs/development/cursor-setup).

## Catalogs

**Basilic playbooks** — [blockmatic/basilic-skills](https://github.com/blockmatic/basilic-skills) on [skills.sh](https://skills.sh/blockmatic/basilic-skills). Each playbook is a top-level skill (`--skill w-plan` or `--all`). Slash names are `/w-plan`, `/w-build`, `/w-review`.

**Matt Pocock pack** — [mattpocock/skills](https://github.com/mattpocock/skills) on [skills.sh](https://skills.sh/mattpocock/skills). Unprefixed: `/grill-me`, `/grill-with-docs`, `/implement`, `/tdd`, `/code-review`, `/ask-matt`. Run `/setup-matt-pocock-skills` once per clone (issue tracker, labels, docs layout). Durable product facts stay in `PRODUCT.md`; Matt may add `CONTEXT.md`.

**Stack skills** — committed here (`next-v16`, `fastify-v5`, …). Not installable from basilic-skills.

```bash
pnpm setup:skills
```

Full installer options: [basilic-skills README](https://github.com/blockmatic/basilic-skills) and [mattpocock/skills](https://github.com/mattpocock/skills).

Root `skills-lock.json` tracks hashes for the two **installed** catalogs only. `pnpm setup:skills` restores the lock after install. Commit the lock after an explicit catalog refresh. Do not commit `.agents/skills/w-*` or Matt’s folders.

## Three kinds

**Tech** — committed `.agents/skills/<topic>-v<major>/` (example: `fastify-v5`). Agent-invocable. Required sections: Scope, Assumptions, Principles, Constraints, Interactions. Force with `@.agents/skills/<topic>-v<major>` or `/<topic>-v<major>`.

**Patterns** — unversioned craft and guidelines (example: `composition-patterns`, `frontend-design`, `vercel-react`). Same loading as tech skills. Matt owns `/prototype`; this repo does not commit an Emil `prototype` skill.

**Workflow** — installed as `.agents/skills/w-<name>/` (example: `w-commit`). Slash is the folder name (`/w-plan`). Set `disable-model-invocation: true`. One-line `description`. Not versioned.

`name` is lowercase letters, digits, and hyphens, max 64 characters, equal to the folder name. Basilic playbook names start with `w-`.

## Workflow install

The published catalog is **42** `/w-*` skills. Git playbooks ship `references/git-publish.md`; `/w-review` ships `references/review-dimensions.md`.

After a refresh, preserve committed stack skills (setup stashes them). Catalog validation: `node scripts/validate-catalog.mjs` in [blockmatic/basilic-skills](https://github.com/blockmatic/basilic-skills).

## Versioning

`<topic>-v<major>` is the **library or SDK major**, not a skill-file revision.

- Library major change → new folder (`next-v17`). Drop the old folder when the repo no longer uses that major.
- Stack skill wording → edit the committed tree in this repo.
- Playbook wording → edit [blockmatic/basilic-skills](https://github.com/blockmatic/basilic-skills), then refresh the lock.
- Matt pack updates → `npx skills@latest add mattpocock/skills --all`, review lock, commit lock only.
- Pattern and craft skills stay unversioned. Library skills use the npm major (`motion-v13`).

This repo’s Expo app is SDK 57; Expo skills are still `*-v55`. Do not invent empty `*-v57` folders.

## Update procedure

```bash
pnpm setup:skills
```

Maintainer preview of a sibling basilic-skills clone:

```bash
BASILIC_SKILLS_LOCAL=1 pnpm setup:skills
```

Refresh hashes (review and commit `skills-lock.json`). Do not run `pnpm setup:skills` afterward if you intend to keep the new hashes.

```bash
npx skills@latest add blockmatic/basilic-skills --all
npx skills@latest add mattpocock/skills --all
```

Do not reformat skill copies to match this repo's Biome rules; `biome.json` excludes `.agents/skills/**`.

Do not `git pull` inside nested `.git` under skills. Do not store project skills only in `~/.cursor/skills/`.

Repo-specific overlays stay in `.cursor/rules/`.

## Design

UI craft also comes from [emilkowalski/skills](https://github.com/emilkowalski/skills). Project tokens in `DESIGN.md` still win.

New or reshaped UI: `/w-ui`. New shadcn primitive: `/w-shadcn` (follow `shadcn-v3`). Visual direction only: `@frontend-design`. Component APIs: `@composition-patterns`. UI code audit: `@web-design-guidelines`. Quality a11y report: `/w-a11y`. Runtime bugs: `/w-debug-browser`. Explore variants: `/prototype` (Matt). Motion: `@animate` (web) or `@animate-expo` (native). Toasts: `@ask-sonner`. Do not run `@pick-ui-library` to replace shadcn in this repo.
