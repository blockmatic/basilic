## Typical order

Compose skills. This is not a router.

1. **Plan** — `/w-plan` (or `/grill-with-docs`) for non-trivial work. Read existing implementation and docs; write Goals, Assumptions (3–5), Tasks, Risks, and References (plain paths). Planning alone does not create a branch or implement code.
2. **Review the plan** — `/w-review-plan` checks scope and ordering. Resolve consequential product or architecture decisions from `PRODUCT.md` and matching MDX/ADRs; continue routine work already authorized.
3. **Implement** — `/w-build` (or `/implement`) delivers complete slices and runs affected checks. Preserve unrelated changes and generated-source ownership. Update matching docs when behavior changes. Update `PRODUCT.md` only when product facts change.
4. **Review the change** — `/w-review` (or `/code-review`) returns evidenced findings and verification limits. Reviews stay read-only unless fixes are requested.
5. **Publish when requested** — `/w-commit`, `/w-push`, or `/w-pr` perform their named actions. `/w-ship` follows installed `git-publish.md`: dirty tree stops (no stash); `/w-commit` may still take task-owned hunks and is the only playbook that owns Conventional Commit format (composers must not paraphrase it). `/w-ship` requires `pnpm qa`. `/w-yolo` does not; it fixes failing or requested local checks without publish. `/w-build` and `/w-commit` update matching MDX and nearest README when behavior or commands change.
6. **Learn** — `/w-retro` identifies concrete improvements; changed conventions belong in existing durable documentation.

Tech skills (`fastify-v5`, `next-v16`, `vercel-react`) load when relevant. Playbooks do not add another backlog or quality policy.

The generator retains this catalog and rewrites its documentation pointers to the adopter’s local docs snapshot. `/release` is advisory and preserves the release tooling’s human gates.

## Checklists and evidence

Playbook bodies are numbered instructions (spec frontmatter, no Purpose/Handoff headings). Reviews use installed `review-dimensions.md`: correctness, callers, failure paths, clarity, architecture, security, performance, verification, and docs. Skip dimensions that are out of scope and say so. Debugging connects a reproduction to its cause and repeats the original scenario after a fix.

Shared references live in installed `workflow/references/`: `authoring.md`, `git-publish.md`, and `review-dimensions.md`. Record checks as passed, failed, not run, or not applicable with a reason. A type check alone does not verify a browser interaction. Documentation changes need proportionate checks; TDD remains explicit through `/tdd` (Matt), `/w-tdd`, or repository requirements. `/w-ship` is the only Basilic playbook that requires `pnpm qa`.

Further polish is later and small. See [Skills](/docs/development/cursor-skills).
