Root `AGENTS.md` plus `.agents/skills/` (after `pnpm setup`) is the contract: versioned **tech** skills, unversioned **patterns**, and **workflow** playbooks (`/plan`, `/build`, `/review`, `/test`, `/pr`). Any agent or IDE that can read those files. If the harness has no `/` menu, open the `SKILL.md`. Do not create a parallel process.

Cursor slash (`/plan` `/build` `/review`), glob auto-attach, and `.cursor/mcp.json` are **adapters**, not the contract. Claude Code, Codex, Gemini CLI, and others use the same tree. Catalog, install flags, and the Emil design pack: [Skills](/docs/development/cursor-skills). Optional Cursor indexing/MCP: [Agent setup](/docs/development/cursor-setup).

Judgment lives in planning and review. Implementation is incremental. See [Engineering in the AI Era](https://gaboesquivel.com/blog/2026-02-engineering-ai-era).

Durable product intent lives in root `PRODUCT.md`. Visual language is root `DESIGN.md`. Technical adopter docs live in `apps/docu`. Installed playbooks come from [`blockmatic/basilic-skills`](https://github.com/blockmatic/basilic-skills) under `.agents/skills/workflow/`. `/tdd` is opt-in. In-app chat is the [demo assistant](/docs/architecture/ai), not this page.

## Sources of truth

Root `AGENTS.md` holds always-on constraints (behavior, naming, file organization, git, GitHub Actions). Glob `.mdc` files under `.cursor/rules/` are file-scoped constraints; Cursor auto-attaches them. **Read** the matching MDX for the task. Do not `@`-attach MDX from rules or skills.

## Guidance hierarchy

| Layer | Role | How it loads |
| --- | --- | --- |
| **AGENTS.md** | Always-on contract | Cursor and Codex read it; Claude via `@AGENTS.md` in `CLAUDE.md`; Gemini CLI via `GEMINI.md`; Antigravity via `.agents/rules/always.md` |
| **Glob rules** (`.cursor/rules/*.mdc`) | File-scoped constraints | Cursor attaches by glob. Other harnesses read the matching file when those paths are in scope (table in `AGENTS.md`) |
| **Workflow skills** (`.agents/skills/workflow/`) | Playbooks | Cursor: `/<leaf>`. Otherwise open `SKILL.md` |
| **Tech skills** (`.agents/skills/<topic>-v<major>/`) | Stack patterns | Agent loads when relevant; `@` or `/` to force |
| **Pattern skills** (unversioned) | Craft and guidelines | Agent loads when relevant; `@` or `/` to force |
| **Indexed docs** | Advisory | Never override `AGENTS.md`, glob rules, or source |

Cursor slash menus, `.cursor/mcp.json`, and glob auto-attach are **Cursor extras**, not the portable contract.

## Slash playbooks

In Cursor chat, type `/` then the skill name.

- **Enter** — attach for this message only
- **Option+Enter** (Alt+Enter) — pin for the session

Invoke playbooks directly. `/workflow` lists the catalog and stops; it does not run `/workflow plan`.

| Task | Invocation | Folder |
| --- | --- | --- |
| Plan a feature | `/plan` | `plan` |
| Implement and verify locally | `/build` | `build` |
| Review a change | `/review` | `review` |
| Diagnose or fix a failure | `/debug` | `debug` |
| Run tests and fix failures | `/test` | `test` |
| Commit intended changes | `/commit` | `git/commit` |
| Push the intended branch | `/push` | `git/push` |
| Create a described PR | `/pr` | `git/pr` |
| Implement through a described PR | `/ship` | `git/ship` |
| Reflect on completed work | `/retro` | `retro` |
| Build or reshape UI | `/ui` | `ui` |
| Explore UI variants | `/prototype` | `prototype` (Emil pack, not under `workflow/`) |

`/build` ends with verified local changes. `/ship` requests implementation, full validation, commit, push, and a described PR. No playbook implies merge or deployment.

Slash names are leaf folders. Removed names map to `/commit`, `/push`, `/pr`, `/ship`, `/ui`, `/tdd`, `/architecture`, and `/refactor` (formerly `/git-commit`, `/git-push`, `/git-create-pr`, `/exec-push`, `/use-frontend`, `/use-tdd`, `/plan-architecture`, `/refactor-code`). When a harness does not expose the slash menu, read the `SKILL.md` under `.agents/skills/workflow/`. Do not create another skills tree. Do not commit `.claude/skills/` copies.

## Typical order

Compose skills. This is not a router.

1. **Plan** — `/plan` for non-trivial work. Read existing implementation and docs; list goals, assumptions, acceptance conditions, dependencies, and verification per slice. Planning alone does not create a branch or implement code.
2. **Review the plan** — `/review-plan` checks scope and ordering. Resolve consequential product or architecture decisions from `PRODUCT.md` and matching MDX/ADRs; continue routine work already authorized.
3. **Implement** — `/build` delivers complete slices and runs affected checks. Preserve unrelated changes and generated-source ownership. Update matching docs when behavior changes. Update `PRODUCT.md` only when product facts change.
4. **Review the change** — `/review` returns evidenced findings and verification limits. Reviews stay read-only unless fixes are requested.
5. **Publish when requested** — `/commit`, `/push`, or `/pr` perform their named actions. `/ship` combines the implementation-to-PR path and requires `pnpm qa`.
6. **Learn** — `/retro` identifies concrete improvements; changed conventions belong in existing durable documentation.

Tech skills (`fastify-v5`, `next-v16`, `vercel-react`) load when relevant. Playbooks do not add another backlog or quality policy.

The generator retains this catalog and rewrites its documentation pointers to the adopter’s local docs snapshot. `/release` is advisory and preserves the release tooling’s human gates.

## Checklists and evidence

The core playbooks use inputs, steps, verification, and a handoff. Reviews inspect correctness, clarity, architecture, security, performance, and the verification claims. Debugging connects a reproduction to its cause and repeats the original scenario after a fix.

Shared completion evidence lives inside the installed `workflow/references/` directory. Record checks as passed, failed, not run, or not applicable with a reason. A type check alone does not verify a browser interaction. Documentation changes need proportionate checks; TDD remains explicit through `/tdd` or repository requirements.

Further polish is later and small. `/tdd` stays opt-in. See [Skills](/docs/development/cursor-skills).
