Root `AGENTS.md` plus `.agents/skills/` is the contract. The **recommended daily workflow** is [Matt Pocock’s skills](https://www.aihero.dev/skills) ([mattpocock/skills](https://github.com/mattpocock/skills)): `/grill-me`, `/implement`, `/tdd`, tutorials, and ongoing maintenance. [Basilic `/w-*` playbooks](https://github.com/blockmatic/basilic-skills) stay installed as a lightweight alternative and as this repo’s git/docs close-out (`/w-commit` … `/w-ship`). Versioned **tech** skills and unversioned **patterns** are committed here. Any agent or IDE that can read those files. If the harness has no `/` menu, open the `SKILL.md`. Do not create a parallel process. Do not `claude plugins install mattpocock-skills` in this repo — `pnpm setup:skills` already copies the pack into `.agents/skills/`.

Cursor slash, glob auto-attach, and `.cursor/mcp.json` are **adapters**, not the contract. Catalog and install: [Skills](/docs/development/cursor-skills). Optional Cursor indexing/MCP: [Agent setup](/docs/development/cursor-setup).

Judgment lives in planning and review. Implementation is incremental. See [Engineering in the AI Era](https://gaboesquivel.com/blog/2026-02-engineering-ai-era).

Visual language is root `DESIGN.md`. Technical adopter docs live in `apps/docu`. Matt `/grill-with-docs` may add `CONTEXT.md`. `/implement` may commit; `/w-build` verifies locally and does not commit. Publish with `/w-ship`. `/tdd` is Matt; `/w-tdd` is Basilic’s opt-in. In-app chat is the [demo assistant](/docs/architecture/ai), not this page. Tracker-backed Matt skills (`/to-tickets`, `/triage`) need `/setup-matt-pocock-skills` once per clone.

## Sources of truth

Root `AGENTS.md` holds always-on constraints (behavior, naming, file organization, git, GitHub Actions). Glob `.mdc` files under `.cursor/rules/` are file-scoped constraints; Cursor auto-attaches them. **Read** the matching MDX for the task. Do not `@`-attach MDX from rules or skills.

## Typical order

Compose skills. This is not a router.

1. **Shape** — `/grill-me` or `/grill-with-docs`. Use `/to-spec` or `/wayfinder` when the thread needs a spec or a multi-session map. `/w-plan` explores via `/w-council` first. Planning alone does not create a branch. Resolve product facts from matching MDX/ADRs, README, and `DESIGN.md`.
2. **Implement** — `/implement` or `/tdd`. Use `/w-build` when you want verified local changes **without** a commit.
3. **Review** — `/code-review` (or `/w-review`). Reviews stay read-only unless fixes are requested.
4. **Publish when requested** — `/w-commit`, `/w-push`, or `/w-pr`. `/w-ship` follows installed `git-publish.md`: dirty tree stops (no stash); `/w-commit` owns Conventional Commit format. `/w-ship` requires `pnpm qa`. `/w-yolo` does not; it fixes failing or requested local checks without publish.
5. **Learn** — `/w-retro` identifies concrete improvements; changed conventions belong in existing durable documentation.

Tech skills (`fastify-v5`, `ai-sdk-core-v7`, `json-render-core-v0`, `eve`, `typesafe-ai`) load when relevant. Playbooks do not add another backlog or quality policy.

The generator retains this catalog and rewrites its documentation pointers to the adopter’s local docs snapshot. `/release` is advisory and preserves the release tooling’s human gates.

## Checklists and evidence

Playbook bodies are numbered instructions (spec frontmatter, no Purpose/Handoff headings). `/w-plan` ships `plan-output.md`. Basilic reviews use installed `review-dimensions.md`: correctness, callers, failure paths, clarity, architecture, security, performance, verification, and docs. Spawn 2–3 read-only explorers that split in-scope dimensions. Skip dimensions that are out of scope and say so. Debugging connects a reproduction to its cause and repeats the original scenario after a fix.

Git playbooks ship `references/git-publish.md`. Record checks as passed, failed, not run, or not applicable with a reason. A type check alone does not verify a browser interaction. Documentation changes need proportionate checks; TDD remains explicit through `/tdd` (Matt), `/w-tdd`, or repository requirements. `/w-ship` is the only Basilic playbook that requires `pnpm qa`.

Further polish is later and small. See [Skills](/docs/development/cursor-skills).
