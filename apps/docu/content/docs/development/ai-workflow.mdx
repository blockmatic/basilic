Development is **Cursor-first**. [Claude Code](https://docs.anthropic.com/en/docs/claude-code) is supported through [`CLAUDE.md`](https://github.com/blockmatic/basilic/blob/main/CLAUDE.md): it follows the same `.cursor/rules` and `.cursor/skills`. Do not run a parallel process.

Judgment lives in planning and review. Implementation is incremental and reviewed. See [Engineering in the AI Era](https://gaboesquivel.com/blog/2026-02-engineering-ai-era).

Index this site and stack docs in Cursor once — [Cursor Setup](/docs/development/cursor-setup).

## Guidance hierarchy

| Layer | Role |
| --- | --- |
| Rules | Global, opinionated, override everything |
| Skills | Local expertise and patterns |
| Model | Reasoning and synthesis |
| Indexed docs | Advisory; never override rules or source |

## Models (30 Aug 2026)

| Model | Use |
| --- | --- |
| **Cursor Grok 4.6** | Default for plan and implement. Grok 4.5 is a cheaper/faster picker option. |
| **GPT-5.6 Sol** | Long-horizon work, large diffs, hard debugging |
| **Composer 2.5** | Fast multi-file execution after a reviewed plan |
| **Claude Code** (Opus 5) | Secondary harness; same rules and skills |

In-app chat (Fastify `/ai/chat`) defaults to Claude Sonnet 4 — that is the product model, not this workflow. See [Self-Hosted LLM](/docs/deployment/self-hosted-llm).

## Workflow

1. **Plan** — Start in plan mode (Grok 4.6, or Sol for large/ambiguous work). Break the task into steps and surface edge cases before coding.
2. **Review** — Read the plan. Check scope, dependencies, and approach. Refine until you would implement it yourself.
3. **Execute** — Follow the plan in small steps. Composer 2.5 is fine for mechanical multi-file edits; stay on Grok 4.6 or Sol when judgment is still required. Test between steps.
4. **Commit** — Ship &lt;30-minute chunks. Easy to review, easy to revert.

CodeRabbit reviews PRs against project standards. Local quality gates are Biome, ESLint, and [pre-commit security](/docs/architecture/security).

You can point agents at MDX pages: `Using the patterns from @api, add an endpoint…`
