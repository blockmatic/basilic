Contract-first API development with **OpenAPI** and **hey-api** ensures end-to-end type safety. OpenAPI specs serve as the source of truth, and hey-api generates type-safe TypeScript clients for multi-language SDKs and AI/MCP integration.

## What is Contract-First Development?

Contract-first development means defining your API contracts **before** implementing the server or client. The OpenAPI spec becomes the single source of truth for:

- Request/response shapes
- Type definitions
- Validation schemas
- API documentation

## Benefits

- ✅ **End-to-end type safety** - Types flow from OpenAPI specs to generated clients automatically
- ✅ **No duplication** - Define once in OpenAPI, generate clients for all languages
- ✅ **Automatic client generation** - hey-api generates fully typed TypeScript clients
- ✅ **OpenAPI standard** - Industry-standard format for API contracts
- ✅ **Framework portability** - Works with Fastify, Express, or any framework
- ✅ **Multi-language support** - Generate clients for TypeScript, Python, Go, Rust, etc.

## Simple Example

**1. Define OpenAPI Spec** (`apps/api/openapi/openapi.json`)

The OpenAPI spec defines the API contract. This can be written manually or generated from code annotations.

**2. Generate TypeScript Client** (`packages/core`)

hey-api generates type-safe clients from the OpenAPI spec:

```typescript
// Generated by @hey-api/openapi-ts
import { createClient } from './gen/client'

const client = createClient({
  baseUrl: 'https://api.example.com',
})
```

**3. Server Implementation** (`apps/api`)

Fastify implements routes that match the OpenAPI spec.

**4. Client Usage** (`apps/web`)

```typescript
import { createApi } from '@basilic/core'
import { useHealthCheck } from '@basilic/react'

const api = createApi({
  baseUrl: process.env.NEXT_PUBLIC_API_URL!,
  getAuthToken: async () => session?.token,
})

// Fully typed API call
const health = await api.healthCheck()

// Or use React Query hooks
const { data } = useHealthCheck()
// data is fully typed from OpenAPI spec
```

## Workflow

1. **Define OpenAPI spec** - Create or generate OpenAPI 3.0 spec in `apps/api/openapi/`
2. **Generate clients** - hey-api generates TypeScript clients in `packages/core` and `packages/react`
3. **Implement server** - Implement routes in `apps/api/src/routes/` that match the spec
4. **Use in client** - Import and use generated typed clients

## Client Consumption

Clients consume the API through generated TypeScript clients:

```typescript
import { createApi } from '@basilic/core'
import { useHealthCheck } from '@basilic/react'

// Runtime-agnostic client
const api = createApi({
  baseUrl: process.env.NEXT_PUBLIC_API_URL!,
  getAuthToken: async () => session?.token,
})

// Fully typed API call
const health = await api.healthCheck()

// Or use React Query hooks (generated from OpenAPI spec)
const { data, isLoading, error } = useHealthCheck()
```

The generated clients:
- Provide full type safety from OpenAPI specs to components
- Handle authentication and headers automatically
- Work with TanStack Query for caching and state management
- Are generated by hey-api from OpenAPI specs

## OpenAPI Integration

OpenAPI 3.0 specs are the source of truth:
- Served at `/reference/openapi.json` (programmatic access)
- Scalar UI at `/reference` (interactive docs)
- MCP integration for AI agents
- Multi-language SDK generation using hey-api and standard OpenAPI tools

### SDK Generation

**TypeScript**: Generated by `@hey-api/openapi-ts` from OpenAPI specs. **Other languages**: Use standard OpenAPI generators (`openapi-generator`, `oapi-codegen`, `progenitor`). All clients are generated from the same OpenAPI spec, ensuring consistency.
